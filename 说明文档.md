# 天地图分析工具-数据库设计说明

| 项          | 内容                          |
|-------------|-------------------------------|
| 文档名称    | 天地图分析工具-数据库设计说明 |
| 版本        | V1.0                          |
| 适用数据库  | SQLite 3.x（兼容MySQL 8.0+/PostgreSQL 14+）|
| 设计日期    | 2026-02-12                    |
| 核心目的    | 持久化存储每次操作的全量数据，保留历史记录，避免文件覆盖 |
| 依赖工具    | Python 3.8+、sqlite3（Python内置）、pysqlite3（可选） |

## 一、数据库选型依据

| 选型        | 优势                          | 适用场景                  | 局限性                  |
|-------------|-------------------------------|---------------------------|-------------------------|
| SQLite      | 1. 无需部署服务，单机即用（Python内置驱动）<br>2. 轻量（单文件存储，默认`tianditu_analysis.db`）<br>3. 读写速度快（单机小规模数据场景）<br>4. 无需配置用户名/密码，零运维 | 单机使用、小规模数据（≤10万条记录）、快速落地 | 不支持高并发（单机单连接足够）、无原生远程访问（需额外配置网络共享） |
| MySQL       | 1. 支持远程访问、高并发<br>2. 生态完善，工具丰富（如Navicat） | 多机协作、大规模数据（＞10万条） | 需部署服务，配置复杂，依赖额外安装 |

**最终选型**：SQLite（优先落地，后续可无缝迁移至MySQL）

## 三、表关联关系

### 1. 关联示意图（文字描述）

tianditu_operations（主表）
├── 1:N → tile_metadata（一个操作对应多张瓦片）
├── 1:1 → merged_maps（一个操作对应一张拼接图）
├── 1:1 → analysis_results（一个操作对应一份分析结果）
└── 1:1 → reports（一个操作对应一份报告）

### 2. 关联规则

- 所有子表通过`operation_id`关联主表，主表删除记录时，子表关联记录自动删除（`ON DELETE CASCADE`）；
- 子表中`operation_id`+核心字段唯一（如`merged_maps`的`operation_id`唯一，确保一个操作仅一条拼接图记录）。

## 四、命名规范

1. **表名**：小写+下划线，前缀`tianditu_`（业务域标识），后缀为功能描述（如`operations`、`tile_metadata`）；
2. **字段名**：小写+下划线，遵循“名词/名词短语”（如`operation_id`、`place_name`），避免缩写（特殊缩写需文档说明）；
3. **文件路径**：统一存储**绝对路径**，避免因程序运行目录变化导致寻址错误；
4. **operation_id**：固定格式`YYYYMMDD_HHMMSS_6位随机串`（如`20260212_153000_8f9e`），通过Python生成，确保全局唯一。

## 五、数据校验规则

### 1. 数值校验（数据库层面+应用层面双重校验）

- 缩放等级：1 ≤ zoom_level ≤ 18（数据库`CHECK`约束+应用层输入校验）；
- 经纬度：中国境内范围（经度73.0~135.0，纬度4.0~53.0），避免无效地理坐标；
- 评分/数量/密度：非负数值（数据库`CHECK`约束）；
- 文件大小/分辨率：大于0（确保文件有效）。

### 2. 格式校验（应用层面实现）

- `operation_id`：匹配正则`^\d{8}_\d{6}_[a-z0-9]{6}$`；
- 时间字段：Python生成`datetime.now().strftime("%Y-%m-%d %H:%M:%S")`，确保格式统一；
- 文件路径：写入数据库前，通过`os.path.exists()`校验文件实际存在。

## 六、扩展说明

### 1. 迁移至MySQL

- 字段类型映射：
  - SQLite `INTEGER` → MySQL `INT`；
  - SQLite `FLOAT(10,6)` → MySQL `DECIMAL(10,6)`；
  - SQLite `TINYINT` → MySQL `TINYINT`；
  - 其他字段类型（VARCHAR/TEXT/DATETIME）保持一致。
- 关联关系：MySQL支持`FOREIGN KEY`，需确保存储引擎为InnoDB（默认）。
